# KISS review, 2026-10-20

Branch `hardening-and-settings` at `7a91074`. Read against AGENTS.md: "Keep the structure; add mechanisms only for measured problems." Nothing in the code was changed for this review.

## Verdict

The hub is in good shape for its size. The expensive mechanisms (the SQLite query index, visibility bitmaps, shared listings, read-on paging, the payload cache, prepared statements, encrypted migration sorts) each have a measured problem and a before/after number in docs/PERFORMANCE.md. They also have a test that guards them. I found no cache, background job or special case in the hot paths that lacks a reason. The extra weight is elsewhere, and none of it is dangerous:

- small helpers written several times (writing a file safely is done six ways);
- about 50 lines of dead code;
- an upgrade path for stores from before 2026-10-09 that every new hub still runs;
- a few config keys nobody sets;
- two ways to call central in the Facility Hub app;
- docs that have drifted from the code in a handful of places.

The newest work (devkey, tokens.go, applyRetries, the background download, the Settings and Refusals pages) is small and direct. Two exceptions: the three dataStore-settings readers are near-copies of each other, and the app's four "read an entry, write it as an admin entry" hooks repeat themselves. Doing everything in the table below would remove roughly 600 lines, about 2 % of the hub, and change no behaviour.

`go vet ./...` is clean. `go test ./...` passes in all 26 packages with tests. I did not run `-race`, the live suite or the perf tests. I did not run the app's tests either: `node_modules` is not installed.

## Keep as is

This complexity is justified. Each has a measurement or a review finding behind it. Do not remove any of it by mistake.

| Mechanism | Where | Why it stays |
|---|---|---|
| Searches split between SQL and Go | `tracker/search.go` | The working list takes 0.03 ms instead of 57 ms, and the heap is 4 MB instead of 1.2 GB (PERFORMANCE History 2026-10-09). Guards: `TestQueryPlansUseIndexes`, `TestFirstPageReadsOnWithoutGaps`, the oracles. |
| Read-on paging (`pagePositions`) | `tracker/pagepos.go` | A device's full download at HC IV size fell from 1 h 14 min to 4 min 10 s. It keeps only a row ID, used once, for at most 10 minutes. Guard: `TestPagesReadOnFromLastPosition`. |
| Decoded-payload cache, 4 096 entries | `tracker/payloads.go` | An Android page fell from 20 ms to 7 ms. It is keyed by nonce, so a changed object always misses. |
| Prepared statements | `store/objects.go:556` | Preparing a statement per object doubled the cost of writes (History 2026-10-09). |
| Visibility bitmaps | `tracker/visibility.go`, `store` | Under 5 MB for 60 users and 750 000 objects. The older design used 1 GB at 10 % of that size. |
| Shared listings (`GroupKey`) and the hourly access refresh | `internal/sync`, `access` | Requests to central fell from 53 000 to 9 400 a day per hub. Guard: the twin users in the access matrix. |
| One write lock in `Store.Tx` | `store/store.go:731` | Without it, writers got "database is locked" on the `pi4` hammer run. |
| Encrypted temporary files for migrations | `store` | A migration ran out of memory at 4.6 M objects; it now takes 26 s. Guard: `TestMigrationOnFullStore`. |
| Event-list indexes, retention stubs | `store` migrations | One device's download of an event program fell from 28 min to 55 s. At `hc4-5y` the data file fell from 16.2 GB to 6.5 GB. |
| Reconnect delay, ±10 % sync jitter | `sync/sync.go:61–75` | Reasoned rather than measured live: 500 hubs start below two pushes a second (PERFORMANCE, "Load on central"). Cheap, and documented in the README. |

## Docs vs code

1. **README, `tls` row:** "issues its server certificate and discards the CA key". The code keeps `ca.key` and renews from it (`hubtls/hubtls.go:262`), as the README's own `data_dir` row says.
2. **README, Configure table:** it lacks `network`, `nm_dnsmasq_dir`, `mdns`, `setup_local_only`, `central_move_after` and `uplink_switch`. The image and `hub init` write `network`, `mdns` and `setup_local_only`.
3. **README, Run:** it lists "simulate uplink cut" as an admin-page action. The action appears only with `uplink_switch: true` (`ui/ui.go:316`). DEPLOYMENT.md says this correctly.
4. **README, Releases:** the steps say the hub pushes its outbox, then downloads. Since S13 the download comes first, in the background, and a later cycle pushes and swaps. DEPLOYMENT.md "Upgrades" is right.
5. **README, Layout:** it lacks `internal/config`, `hubtls`, `mdns`, `netsetup` (with `nmfake`), `logfile`, `diskfree` and `testkit/provision`.
6. **README, `internal/compat`:** it says "**All** DHIS2-version-specific request and response handling". In fact `sync/aggregate.go:141` reads both the 2.42 and the 2.43 shapes of `dataValueSets` in place, and `core/refresh.go:443` parses 2.43's `enrollmentCategoryCombo`. Parsing both shapes in place is simpler than a version branch, so change the sentence, not the code.
7. **Code cites doc sections that do not exist:**
   - PERFORMANCE.md "The query index in SQLite" (`tracker/index.go:23`, `store/store.go:232`);
   - DEPLOYMENT.md "Where .local fails" (`core/reach.go:22`, `e2e/reach_test.go:13`);
   - DEPLOYMENT.md "Sizing" (HARDWARE-TESTING.md:18). It is PERFORMANCE.md, "Sizing for a busy urban HC IV".
8. **Stale comments:**
   - `tracker/search.go:272` mentions "the result cache", which was removed on 2026-10-14.
   - `upgrade/upgrade.go:380`: `WaitDownload` is "for tests, and a clean shutdown", but nothing calls it at shutdown.
   - `mdns/mdns.go:41`: `Silenced` is "for the hub's page", but no page reads it. Show it, or drop the method.
   - `compat/compat.go:66`: the comment "Supported lists…" sits above `registry`.
   - `cmd/hub/pprof.go` points to PERFORMANCE.md, which does not mention `HUB_PPROF`.
9. **PERFORMANCE.md, "Security of the SQLite index":** "Sorting stays in memory (`temp_store=memory`)". Since 2026-10-17, migrations sort through encrypted temporary files, as the same document says further down. Add that exception.
10. **docs/reviews/README.md:** its table has no row for this file or for `docs/security-review_2026-10-20.md`. The second file also sits outside `docs/reviews/`. I did not edit the table.

## Smaller items

- `config/ports.go:42` writes its own `itoa`; `strconv.Itoa` does the same. `hubtls/hubtls.go:157` `bytesEqual` is `bytes.Equal`.
- The test `u.NeedsLogin || (!u.HasPAT && !u.HasPassword)` appears four times (`sync/sync.go:107, 614`, `sync/aggregate.go:47`, `core/refresh.go:343`). Make it a method on `store.User`.
- The layout `"2006-01-02T15:04:05.000"` is written out in 7 places, although `tracker.DHIS2Time` exists. `core/aggwarn.go:41` repeats `aggregate.naive`. Use one constant. Leave the two date parsers alone: `tracker.parseTime` must accept what the SQL side accepts, so it falls under the search guards.
- `compat.SupportedMajors()` hard-codes `[42, 43]`, which `registry` already holds.
- `core/tokens.go:27`: central's token lifetime is kept within 7–365 days, but the `pat_expiry_days` fallback is not.
- Which files `devkey` seals is decided in three places: the `Files` list, the `.key` suffix in `hubtls`, and the direct `devkey.WriteFile` calls. Item 2 reduces this to two.
- `requests.log` (with `log_requests`) grows without limit, while `internal/logfile` already has a capped file. Use it.
- `Upgrader.download`, a `WaitGroup`, exists only for tests. `sync.diskFree` and `sync.usbStatus` are one-line wrappers.
- `store.AllObjects` (`store/objects.go:409`) serves only `bench_test.go`. It can move to the test file.
- The app writes its own base64 (`hubaccount/approve.ts`, about 35 lines). `atob`/`btoa` with the strict-form check is shorter. "404 means empty" is coded three times (`api/useApi.ts:72`, `hubs/useHubs.ts:182`, `hubs/refusals.ts:93`).
- **Not measured since it was added:** the heartbeat carries 90 days of history (since 2026-10-17), up to 100 refusal groups, and addresses. That is roughly 15 KB, 96 times a day, per hub, written into central's dataStore: about 0.7 GB a day for 500 hubs, by my estimate. The "Load on central" numbers date from 2026-10-10. Re-run `TestCentralLoad` with request bodies counted. If it matters, send the history once a day.
- **The measured reason has gone:** the garbage-collector limit at 70 % of RAM (`cmd/hub/memlimit.go`) dates from the in-memory design, when the hub used 1 GB. Today the hub holds about 20 MB. It is cheap insurance; remove it only after a ladder run shows the same peak memory without it.
- **"Simulate uplink cut"** keeps a second connectivity state in the monitor (`Force`, `Reachable`, `ForcedOffline`), off in the field. If demos can cut the network instead (the test kit already does), it can go, with `e2e/account_test.go:321` moved to the test kit's cut.
- **CI:**
  - The Windows installer is built and checked twice: `windows.yml` on Linux and `macos.yml` on a Mac. Keep the Mac job only if building on a Mac is a supported path. The recent 7-Zip fixes on `main` came from it.
  - No workflow runs `go test` on Linux on push; Linux tests run only on release tags. None runs the `-race` set that AGENTS.md asks for. One Linux job with `go vet`, `go test` and `go test -race` on the four packages would cover both.
- `internal/core` has 3 400 lines and 36 lines of unit tests. It is covered through `internal/e2e`. That is fine, but a bug there shows up as an e2e failure far from its cause.
