Tested against DHIS2 2.42 and 2.43, with the Sierra Leone and Laos demo databases. Hubs upgrade when a country chooses 0.2.0 on the Facility Hub app's "Hub version" page. The upgrade adds one table to the hub's store and changes no existing data.

### Sync fixes

- **Generated IDs are never handed out twice.** When central failed in the middle of a request, a value could be given to two records. Values now come from the hub's own pool when central fails.
- **Short ID patterns.** When a pattern such as `ORG_UNIT_CODE/RANDOM(###)` runs low, the hub asks for fewer values and says on its page when central cannot fill its pool. Check these patterns on central before the first hub (DEPLOYMENT.md, "On central, before the first hub").
- **Records deleted on central leave Android tablets,** also when the tablet last synced with the hub while the facility was offline.
- **Events are listed in central's order** when sorted by their scheduled or completion date.
- **Aggregate forms:** data input periods open and close when central's do (2.43); a data set taken off the facility is noticed; number values are checked offline the way central checks them.
- **Notes added offline** in Capture web reach central, as their author.
- **Smaller fixes:** "Last push" moves only when central answered; the reserved-value pool is refilled before the pull; `system/info` answers offline for every staff member.

### New

- **Overwrite count.** The hub counts offline saves that replaced a newer change on central (one save in ten is checked), and the Facility Hub app shows them on the hub's page. A country can turn it off: `facility-hub-config/overwrites` = `{"off": true}`.
- **TPM status.** The heartbeat and the Facility Hub app say whether a hub's keys are sealed by a TPM. A TPM is recommended, not required.
- **`/hub/status` `pending`** now also counts aggregate values and notes waiting to be sent.

### Windows

- **The installer installs for the whole PC only** and needs administrator rights. Installing for one user is no longer offered. No earlier release shipped an installer, so nothing needs moving.
- **Safer upgrades and uninstalls:** an upgrade never replaces a working hub with an empty one; an install that stops leaves the hub as it was; uninstalling checks that Microsoft Defender's exclusion is gone.
- **The installer says when the PC has no usable TPM.** Windows 11 is supported; Windows 10 is untested.
- **No Windows installer in this release:** there is no code-signing certificate yet. `hub-windows-amd64.exe` is not an installer: it is the hub program that installed Windows hubs download when they upgrade themselves. Don't run it by hand.

### Before a national rollout

Hubs write the record IDs and usernames of refused and overwritten saves to central, for the Facility Hub app. Have the country's data protection lead sign off on this, and on who may read those entries (DEPLOYMENT.md, "On central, before the first hub", step 5).
